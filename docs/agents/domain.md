# Domain documentation

This project has a single domain context.

## Before exploring the codebase

1. Read `GLOSSARY.md` at the repository root.
2. Read the ADRs in `docs/adr/` that apply to the area being explored.
3. When working on the first version of review, read `docs/review-v1.md`.
   This document defines the agreed behavior, not the implementation status.

If a document is missing, continue without suggesting its creation solely
to configure the skills.

## Terminology

Use the terms defined in `GLOSSARY.md` in issues, change proposals,
hypotheses, and test names.

If a concept is missing from the glossary, check whether it corresponds
to an existing term. Flag a genuine gap for resolution during domain
modeling work.

## Architectural decisions

If a proposal contradicts an existing ADR, identify the document and
explain why the decision should be reconsidered.

## Preserving existing documentation

The skills setup preserves the existing `GLOSSARY.md`, `docs/adr/`,
and `docs/review-v1.md` at their current locations without changing
their contents.
